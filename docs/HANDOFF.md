## 5. データ仕様

### 問題（bank.json の1件）

```json
{"f":"業法","t":"免許","ref":"R06-38-1","s":"問題文","a":0,"e":"解説","m":"覚え方"}
```

| キー | 意味 |
|---|---|
| f | 分野：`業法`／`権利`／`法令`／`税他` |
| t | 論点名（46種） |
| ref | 出典「年度-問-肢」（例 R06-38-1、R03s＝12月試験、H30＝平成30年）。`確認` は自作の確認問題 |
| s | 問題文（○×で答える1文） |
| a | 正解 1＝○、0＝× |
| e | 解説（根拠条文つき） |
| m | 覚え方（短いフレーズ） |

- 問題の安定キー：`f|t|ref`（同じ組み合わせが重複したら `#2`, `#3`…）。学習記録はこのキーで保存するので、**問題文を直してもキーは変えない**こと。

### 解説（lessons.json）

キーは `分野|論点`（例 `業法|免許`）。値は `{pts: 要点[], traps: ひっかけ[], rel: 付随論点キー[], bridge: つなぎ文, sys: 体系解説}`。

`sys`（2026-10-07追加）＝間違えた論点を体系的に復習するための図表データ：
`{overview: 位置づけ, tree: [{h: 大項目, items: 小項目[]}]（体系図）, flow: {title, steps[]} | null（流れ図）, tables: [{title, head[], rows[][]}]（比較表）}`
- 解説は2段構成（2026-10-07 本人要望「長すぎる→間違えた範囲に絞り、広げる部分はリンクで」）
  - 1段目（復習画面）：間違えた問題 → 間違えた範囲の解説（体系図の該当1枝 `relatedBranch()`、関係する表の行だけ最大4行 `relatedRows()`、関係するひっかけ最大2件 `relatedTraps()`）→「体系的に広げる」（全項目チップ・体系ページへのリンク・つながる論点リンク）→ 確認例題3問
  - 2段目（体系ページ、Screen `deep`）：全体像ツリー（押した項目へスクロール＆枠で強調）→ 流れ図 → 比較表（全行）→ 要点・ひっかけ → つながる論点（さらに別論点の体系ページへ。パンくず表示）→「復習に戻る」
- 2026年4月1日時点の法令で別担当が検証済み（区分所有法改正、不動産取得税の免税点16万／66万／34万円、法定利率3%、重説の追加事項 等を反映）
- 本文で断定せず未記載にしている事項（今後追記候補）：拘禁刑導入前の刑の経過措置、改正区分所有法の定足数の規約緩和と60条の決議要件、開発許可のレッドゾーン範囲、2025年建基法改正の構造規定、盛土規制の定期報告・完了検査期限、印紙税の具体税額、買換え特例の細目、鑑定評価の細目、機構の買取条件、景品の上限額・規約の最新文言

### 学習記録（Progress）

```ts
{ v: 2, hist: { [問題キー]: {n: 解いた回数, c: 正解数, last: 1|0} },
  set: { round: 0-4, scores: number[] }, log: [{at, round, score, sec}], voice: boolean }
```

- Web版のサーバー保存先：アーティファクトDBの `data/users/<uid>/progress`（同じ形。`voice` はWeb版では端末側）
- Web版の書き出し形式：`"TKM1:" + base64(UTF-8 JSON {hist,set,log})` → アプリ版でも同じ形式で読み込めるようにすると、Web版の記録をアプリへ移せる

| キー | 意味 |
|---|---|
| id | 安定キー（数値）。変えない・使い回さない |
| ref | 出典（例 `2026年度 2月6日 Ⅰ-A-イ`） |
| f／t／y | 分野／論点／年（紀元前はマイナス） |

## 6. ロジック仕様（変えるときは本人に確認）

| 項目 | 仕様 |
|---|---|
| 1回の構成 | 10問・制限10分（600秒）。経過時間は開始時刻から計算 |
| 分野比率 MIX | 第1〜3回：業4・権3・法2・税1／第4回：業4・権3・法1・税2／第5回：業4・権2・法1・税3 → 5回で 業20・権14・法8・税8 ＝本試験50問の比率 |
| 出題の優先度 | 未出題 → 前回不正解 → 解いた回数が少ない順。同じ論点が重ならないよう分散 |
| 判定（1回） | 8問以上＝合格圏、7問＝合格ライン上、6問以下＝要復習 |
| 判定（5回合計） | 37点以上＝安全圏、35〜36点＝合格ライン（7割）、それ未満＝あと何点 |
| 論点の状態 | 未着手／要復習（直近不正解あり or 正答率60%未満）／習得中（80%未満 or 5回未満）／習得 |
| 立教の出題 | 10問・10分。分野ごとの問題数に比例して配分（世界史：欧中2・欧近2・西南ア1・東ア1・20世紀4／日本史：古代2・中世2・近世2・近代3・現代1）。順番は混ぜる。判定はWeb版と同じく8問以上／7問 |
| 復習の流れ | 間違えた論点ごとに「間違えた問題 → 解説（要点・ひっかけ）→ 付随論点 → 確認例題3問（`確認` 以外の過去問を優先、間違えた問題は除外）」 |

## 6.5 合格の見込み・分野別テスト（2026-10-08 追加）

| 項目 | 仕様 |
|---|---|
| 合格の見込み | 全回答の分野別正答率から本試験50問（業20・権14・法8・税8）の得点を3,000回シミュレーション（`passEstimate()`）。正答率の不確かさはベータ分布。○×→4択は `toExam(p,k)`：各肢を「確信して正しい S／迷う U（半々）／確信して誤る W」に分け（p=S+U/2、k=誤りのうち迷いの割合）、確信した肢→なければ迷う肢（消去法・2択絞り込み）→なければ4肢から選ぶモデル。3通り表示：慎重 k=0（○×80%→62%）、標準 k=0.5（→71%、見出し）、消去法が効く k=1（→82%）。合格確率は合格点33〜37点を等確率とした平均（2026-10-08 本人指定「例年33〜37点」「消去法・2択も勘案」）。30回答未満は非表示。乱数は固定シード |
| 直近10問 | 論点ごとに直近10問の正誤を記録（`r10`：キー「分野\|論点」→ '1'/'0' の文字列、最大10文字、古い→新しい。`record()` で更新）。順番の記録がない既存データは各問の最後の結果で補完（`backfillRecent()`）。論点マップは「直近%/問数・全%」を表示。**合格確率は直近10問（論点ごとを分野で合算）の正答率で計算**、直近がない分野は全体を使う（2026-10-10 本人要望）。Web版はサーバー保存・書き出しにも `r10` を含める |
| 論点マップの色 | **直近10問の正答率**で6段階（`topicTier()`、Web版は `tier()`）：濃い緑＝100%／緑＝80%以上／黄＝60〜79%／橙＝40〜59%／赤＝40%未満／無色＝未着手。直近が5問未満は点線・薄い色（参考値）。表示専用で、「要復習」一覧は従来どおり `topicState()`（全体正答率＋最後の誤答）（2026-10-10 本人要望）。橙は新トークン `or`/`orSoft`（Web `--or`/`--or-soft`） |
| 伸ばせる分野 | 本試験で落とす見込みの点（配点−予想点）が最大の分野を推奨 |
| 分野別10問テスト | `buildFieldExam()`：その分野から10問（未出題・前回不正解を優先、論点分散）。5回セットには入れず、履歴に `field` 付きで記録。**1問答えるごとに正誤・答え・解説・覚え方を即表示**（答えは確定、問番号の丸が正誤色に。2026-10-09 本人要望）。**5回セットの10問テストも同じく1問ごとに即表示に変更**（2026-10-10 本人要望。以前は最後にまとめて採点） |
| 過去問の4択に戻す | `fourChoice()`（Web版も同名）：出典「年度-問番号-肢」の肢を `FOUR_GROUPS` で元の4択（616問）にまとめ、肢ごとの判断確率から4択1問の正解率を推計。解いた肢＝(c+論点率)/(n+1)、未回答・データにない肢＝論点率。論点率は直近10問を分野率5問分でならす（分野率も全体へ5問分）。通常の4択は `fourFromLimbs(ps, 正解位置, k=0.5)`（toExam と同じモデル、肢ごとに p が違う版）を正解位置4通りで平均、個数・組合せ（肢ラベルがア〜エ）は4肢の積で近似。ホームに「過去問の4択に戻すと」カード（低い順6問／すべて表示、平均・3肢以上解いた問題の平均、○×換算との比較）。**合格確率の計算には使っていない**（表示のみ） |
| 問題の追加 | 2026-10-08に過去問（H27〜R07、takken-success.info の解説を参照し自作文で作成）から966問追加、別担当が現行法で検証済み。未取得：R03s-45,46,49,50、R04-05,07,08,09,28,40、R05-01,04,05,06,08（取得許可が得られず） |

## 7. 開発コマンドと環境の注意

```bash
npm install
npx expo start        # Expo Go（iPhone）でQRを読む
npm test              # ロジックテスト（比率・重複なし・5回で一周・復習・全論点に解説）
npm run typecheck     # 型チェック
python3 web/build.py  # Web版を再生成
```

- `npx expo install` はネットワーク制限のある環境では失敗することがある。その場合は `node -e "console.log(require('expo/bundledNativeModules.json')['<パッケージ名>'])"` で対応バージョンを調べて `npm install <pkg>@<ver>` する
- Web表示（react-native-web）も入っているので、`npx expo export --platform web` で画面確認ができる
- Web版HTMLをローカルで開くときは `<meta charset="utf-8">` を付けないと文字化けして動かない（公開時はプラットフォームが付ける）

## 9. 権利・表現の注意

- 法律の条文・知識そのものは著作権で保護されない（著作権法13条）。参考書の文章・図表・構成をそのまま写すのは不可
- 過去問本文の扱いは実施機関の回答を待つ。回答次第で、出典表記の仕方や問題文の書き換えを判断
- 慶應義塾大学の試験問題公開ページには「公開された入試問題を二次的に利用する場合は、改めて著作権許諾処理を閲覧者ご自身の責任において行う」とある。慶應の問題集は設問文・リード文・史料文を使わず、問われた知識だけを使って問題文と選択肢を独自に作成した（作成後に試験の文面との近さも点検して言い換え済み）。**有料アプリに入れる前に専門家の確認が必要**
- 立教・慶應とも「公式教材ではない」旨をフッター（Web版）に表示している。アプリ版でも同じ表示を入れる
- 宣伝やストア説明文で「合格保証」などの誇大表現は使わない（景品表示法）
- 担当者（Claude）は弁護士ではないので、権利の最終判断は専門家に確認
