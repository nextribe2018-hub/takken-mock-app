# 校閲（事実確認）の手順

別の担当者が作った4択問題集を、厳しく点検して直接直す。日本語で作業する。

## データ形式
{"id","k"(past/plan),"ref","f"(分野),"t"(論点),"y"(歴史のみ),"p"(本文・任意),"q","c"(正解は c[0]。"last":true かつ "a" があるときは c[a]),"e"(解説),"m"(覚え方)}
作成ルールは guide-common.md と guide-subjects.md（同じ docs/content フォルダ）を参照。

## 1問ずつ確かめること
1. 正解が正しく、問題文の条件で一つに定まるか（別解になりうる誤答がないか）。英語・国語は、誤答が本文や文法上ほんとうに成り立たないか。
2. 誤答がすべて確実に誤りか。解説内の誤答の説明も正しいか。
3. 問題文・本文・解説・覚え方の事実（年号・人名・用語・文法・語義・数値・法令）が正確か。教科書（税理士は条文・通達・会計基準）の標準的な内容と表記に合わせる。幅のある数値は断定しない。
4. 正誤判定・年代整序・組合せ・整序（並べ替え）は、正解の組み立てを一つずつ検算する。計算・数値は Python で検算する。
5. past：公式解答がある場合は一致するか。ref（年度・日程・大問・問番号）が素材と合っているか。
6. 著作権：試験の設問文・リード文・本文（英文・現代文・史料の現代語訳）をそのまま、またはほぼそのまま写していないか。素材PDFと照合し、近い言い回しは言い換える。英語・現代文の本文は自作か（実在の文章の転載でないか）。古文・漢文は著作権の切れた古典の原文か。
7. 歴史の y（中心年）が内容と合っているか。

作成者が「不安が残る」と挙げた問題は必ず判断して直す。

## 直し方
- 誤りは JSON を直接直す。直せない・正解が一つに定まらない問題は、同じ分野・同じ区分（past は同じ設問の知識、無理なら plan）の新しい問題に差し替え、問題数を保つ。id は 1 からの連番を保つ。
- 直す前のファイルを <元の名前>.bak.json として同じフォルダに残す。
- 直したら必ず `python3 scripts/check-questions.py <ファイル> <問題数> <history|lang>` を実行して OK にする。

## 最後の報告（短く）
- 直した問題：id と「何が誤りで、どう直したか」を1行ずつ（言い換えだけのものは id の列挙でよい）
- 差し替えた問題の id
- 判断がつかず残した点
