# 問題作成の共通ルール（全科目）

## データ形式（JSON 配列。キーはこれ以外を使わない）
{"id":1,"k":"past","ref":"2026年度 前期A 1/24 〔一〕 問3","f":"<分野>","t":"<論点名・短く>","y":1776,"p":"<本文（必要なときだけ）>","q":"<問題文>","c":["正解","誤答1","誤答2","誤答3"],"e":"<解説>","m":"<覚え方・要点>"}

- id：1 からの連番。past を先に、そのあと plan。
- k："past"（過去問ベース）または "plan"（想定問題）。
  - past：公式に公開された試験で問われた知識・技能（正解になる用語、文法事項、語彙、論点、解法）をもとに、新しく作り直した問題。ref は「<年度> <日程・学部> <大問> <問番号>」を素材の表記に合わせて書く。
  - plan：公式の出題方針・出題意図と過去問の形式に合わせて自作した問題。ref は必ず「想定問題」。
- f：分野。セットごとに4〜6個を決め、全問で同じ文字列を使う。各分野10問以上。
- y：歴史（日本史・世界史・地理の歴史的事項）だけ付ける（中心年の整数、紀元前はマイナス）。英語・国語・数学・理科・税理士には付けない。
- p：本文・資料（読解の文章、計算の条件表など）。問題ごとに持たせる（同じ本文を複数問で使うときは各問にコピーしてよい）。60〜1800字。
- c：4〜5個、重複なし。正解は必ず c[0]（アプリが表示時にシャッフルする）。
  - 「すべて正しい」「あてはまるものがない」を最後に置く問題は "last":true。その最後の選択肢が正解のときだけ "a":<番号>。全体の2割以内。
- q：歴史は260字以内、それ以外は320字以内。
- e：120〜300字程度。なぜ正解か＋各誤答がなぜ違うか。
- m：30字前後の覚え方・ポイント。
- 文体は「です・ます」。高校生（税理士は受験生）に分かる言葉。

## 著作権（厳守）
- 試験問題の設問文・リード文・本文（英文・現代文の文章・史料の現代語訳・図表）を写さない。ほぼ同じ言い回しも不可。必ず自分の言葉で一から書く。
- 英語・現代文の本文はすべて自作する（実在の文章・記事・書籍の文を使わない）。
- 古文・漢文は、著作権の切れた古典作品の原文なら使ってよい（作品名を ref か解説に書く）。ただし市販の注釈・現代語訳は写さない。現代語訳は自分で作る。
- 地図・図版・グラフ・写真が必要な設問は使わない（知識だけで答えが決まる形に作り直せるならよい）。

## 正確さ（最優先）
- 正解が一つに定まる問題だけを作る。誤答は確実に誤り、かつ紛らわしいものにする。
- 史実・用語・文法・法令は高校教科書（税理士は条文・通達・会計基準）の標準的な内容と表記に合わせる。自信のない事実は使わない。
- 数値の答えがある問題（数学・理科・計算）は、必ず Python で計算して確かめてから選択肢を作る。誤答は典型的な計算ミスの値にする。
- past は、公式の解答・解答例がある場合は必ず照合する。公式解答がない設問は、正解を自分で確実に確定できるものだけ使う。

## 検査（必ず OK にする）
python3 scripts/check-questions.py <出力ファイル> <問題数> <history|lang>
（y を付ける歴史系は history、それ以外は lang）

## 最後の報告（短く）
- 問題数（past/plan・分野別）、使った分野名
- 使えなかった設問とその理由
- 正解に少しでも不安が残る問題の id と理由
